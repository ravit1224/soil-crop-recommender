# 토양 조건별 작물 추천 (Soil-based Crop Recommender)

토양 검정 결과(질소·인·칼륨·pH)와 그 지역의 기후를 입력하면, 머신러닝 회귀 모델이 작물별 예상
수확량을 계산해서 "이 땅에서는 어떤 작물이 평소보다 잘 자랄지"를 알려 주는 터미널(CLI)
프로그램입니다.

> 고려대학교 「데이터과학과인공지능」 과제 — 데이터 기반 예측 모델 및 서비스 개발하기 (개인 과제)
>
> GitHub 저장소: https://github.com/ravit1224/soil-crop-recommender

---

## 1. 왜 이 주제를 골랐나

환경·조경 쪽으로 진로를 생각하고 있어서, 땅(토양)과 식물을 데이터로 연결해 보는 주제를 하고
싶었습니다. 같은 밭이라도 어떤 작물을 심느냐에 따라 수확량이 크게 달라지는데, 보통은 경험이나
주변 농가의 이야기에 기대서 정하는 경우가 많습니다. 토양 검정 결과처럼 이미 숫자로 나와 있는
정보만으로 "이 토양에는 무엇이 잘 맞는지" 근거를 보여 줄 수 있으면 실제로 도움이 되겠다고
생각했습니다.

처음에는 작물 이름을 바로 맞히는 **분류** 문제로 생각했지만, 과제 조건이 **회귀** 문제여서
방향을 바꿨습니다. 모델은 "이 조건에서 이 작물을 심으면 수확량이 얼마나 나올까"라는 숫자를
예측하고, 추천은 그 예측값을 비교해서 만듭니다. 이렇게 하니 "추천"뿐 아니라 "얼마나 나올지",
"토양을 바꾸면 얼마나 늘지"까지 한 모델로 답할 수 있었습니다.

## 3. 어떤 변수를 썼고, 무엇을 뺐나

변수를 고를 때 가장 신경 쓴 건 **정답이 새어 들어가거나 같은 정보가 두 번 들어가지 않게** 하는
것이었습니다.

**입력으로 쓴 9개**

| 구분 | 변수 | 설명 |
|---|---|---|
| 토양 (4) | `n`, `p`, `k`, `ph` | 토양 질소·인·칼륨, 산도 |
| 기상 (3) | `avg_temp_c`, `total_rainfall_mm`, `avg_humidity_percent` | 연평균 기온, 연 강수량, 연평균 습도 |
| 재배 (2) | `crop`, `season` | 작물 종류, 재배철(카리프·라비·연중 등) |

**뺀 변수와 이유**

| 변수 | 뺀 이유 |
|---|---|
| `production`, `area` | `yield`가 사실상 `production ÷ area`로 계산된 값이었습니다(비율 중앙값 0.996). 넣으면 모델이 정답을 그대로 받아 가는 셈이라 제외했습니다. |
| `fertilizer`, `pesticide` | 면적으로 나눠 보니 같은 해에는 모든 행의 값이 똑같았습니다(연도 안 표준편차 ≈ 0). 즉 "그해 전국 평균 × 면적"이라, 연도와 면적 정보를 다시 넣는 것과 같습니다. |
| `state` | 토양값이 주마다 하나로 정해져 있어서, 주 이름과 토양 4개 변수가 같은 정보를 담고 있습니다. 사용자는 주 이름이 아니라 토양 검정값을 입력하므로 토양 변수만 남겼습니다. |
| `year` | 평가를 연도로 나누는 데만 쓰고, 사용자가 입력할 수 없는 값이라 입력 변수에서는 뺐습니다. |

남은 수치 변수 7개끼리도 겹치는지 다중공선성(VIF)으로 확인했습니다. 가장 높은 pH도 8.6으로,
흔히 쓰는 기준인 10보다 낮아서 모두 남겼습니다. 상관계수 그림은 `figures/eda_correlation.png`에
있습니다.

| 변수 | n | p | k | ph | 기온 | 강수량 | 습도 |
|---|---|---|---|---|---|---|---|
| VIF | 4.1 | 5.1 | 2.0 | 8.6 | 1.7 | 1.8 | 3.9 |

## 4. 전처리 과정

1. **공백 정리**: 작물·재배철 이름 뒤에 공백이 붙어 있어서(`'Kharif     '`) SQL의 `TRIM`으로 정리했습니다.
2. **중복 확인**: (작물, 연도, 재배철, 주) 조합 기준 중복 0건.
3. **추천할 수 없는 항목 제외**: `Other Kharif pulses`처럼 여러 작물을 묶은 집계 항목, 수확량
   단위가 '개수/ha'인 코코넛 (1,220행).
4. **수확량 0 제거**: 재배 실패나 미집계가 0으로 적힌 행 (97행). 로그 변환도 할 수 없습니다.
5. **입력 오류 제거**: 같은 작물 안에서 log(수확량)의 수정 z-점수가 3.5를 넘는 행 (321행).
   양파 381톤/ha, 옥수수 990톤/ha, 델리 감자 311톤/ha처럼 농학적으로 불가능한 값들이 걸렸습니다.
   처음엔 기준을 5로 느슨하게 잡았는데, 이런 값이 몇 개만 남아 있어도 평가 R²가 0.632까지
   떨어졌습니다. 오차가 큰 행을 뽑아 보니 평가 구간 오차의 약 78%가 안드라프라데시주 양파 두 행에서
   나오고 있어서, 기준을 3.5로 바꿨습니다. 이때의 실행 기록과 기준별 비교는
   [docs/outlier_experiment.md](docs/outlier_experiment.md)에 남겨 두었습니다.
6. **관측치가 너무 적은 작물 제외**: 100건 미만인 3종 (케사리콩, 카다멈, 구아르콩).
7. **최종 데이터**: 17,854행, 작물 45종, 재배철 6종.

수치 변수의 표준화와 범주 변수의 원-핫 인코딩은 `ColumnTransformer`로 **파이프라인 안에** 넣어서,
교차검증 때 검증 데이터 정보가 전처리에 섞이지 않도록 했습니다(8장 데이터 누수). 수확량은 오른쪽
꼬리가 긴 분포여서(`figures/eda_target_distribution.png`) `TransformedTargetRegressor`로 log1p
변환해서 학습하고, 예측할 때는 원래 단위로 되돌립니다.

**9장 비지도 학습은 탐색용으로 사용**했습니다.
- 주별 토양·기후 프로필을 표준화한 뒤 K-평균으로 묶고(실루엣 점수로 k=2 선택), PCA 2차원으로
  그렸습니다(`figures/eda_soil_clusters.png`). 비가 많은 동북부·산간·서해안 지역과, 북부·중부 평야 지역으로 나뉩니다.
- IsolationForest로 남은 데이터의 이상치를 다시 점검했는데, 대부분 가뭄·폭우가 있던 해의 실제
  관측이라 지우지 않았습니다.
- 두 결과 모두 모델 성능을 올리는 용도로는 쓰지 않았고, 데이터를 이해하는 데만 썼습니다.

## 5. 모델 비교와 튜닝

**평가 방식**: 1997~2016년 데이터로 학습하고 **2017~2020년을 예측**해서 평가했습니다. 무작위로
나누면 같은 주·같은 작물의 바로 옆 연도가 학습과 평가에 섞여서 점수가 부풀려지기 때문에, 실제로
"앞으로의 수확량"을 맞히는 상황과 같게 만들었습니다. 평가 데이터는 알고리즘 선택이나 튜닝에는
전혀 쓰지 않았고, 최종 모델이 정해진 뒤 성능·기준선·중요도를 계산할 때만 사용했습니다.

**학습 데이터에서 5겹 교차검증(cv=5)으로 8개 알고리즘을 비교**했습니다.

| 알고리즘 | CV R² (평균 ± 표준편차) | CV RMSE |
|---|---|---|
| 랜덤 포레스트 | **0.949 ± 0.006** | 2.65 |
| 보팅 (랜덤 포레스트 + 그레이디언트 부스팅) | 0.947 ± 0.009 | 2.68 |
| 그레이디언트 부스팅 (HistGradientBoosting) | 0.937 ± 0.012 | 2.95 |
| 결정 트리 (max_depth=12) | 0.924 ± 0.012 | 3.23 |
| k-최근접 이웃 (k=10) | 0.884 ± 0.048 | 3.94 |
| 선형 회귀 | 0.807 ± 0.019 | 5.15 |
| 릿지 | 0.805 ± 0.020 | 5.18 |
| 라쏘 | 0.797 ± 0.026 | 5.29 |

선형 모델은 작물별로 토양·기후에 반응하는 방식이 다른 것(상호작용)을 잘 표현하지 못해서 점수가
낮았고, 트리 기반 앙상블이 가장 좋았습니다.

**하이퍼파라미터 튜닝**은 상위 두 앙상블을 서로 다른 방법으로 했습니다(7장).

| 모델 | 방법 | 탐색 범위 | 결과 |
|---|---|---|---|
| 그레이디언트 부스팅 | `GridSearchCV` (16개 조합 × 5겹) | learning_rate, max_iter, max_leaf_nodes, min_samples_leaf | CV R² 0.937 → 0.943 |
| 랜덤 포레스트 | `RandomizedSearchCV` (6회 × 5겹) | n_estimators, max_depth, min_samples_leaf, max_features | CV R² 0.949 → 0.949 |

랜덤 포레스트는 기본값으로도 이미 성능이 좋아서 튜닝 효과가 거의 없었습니다. 최종 모델은 교차검증
점수가 가장 높은 **랜덤 포레스트**(n_estimators=174, max_depth=25, min_samples_leaf=3,
max_features=0.8)입니다.

## 6. 최종 성능 (2017~2020년 평가 데이터, 2,898행)

| 지표 | 최종 모델 | 기준선* |
|---|---|---|
| **R²** | **0.898** | 0.705 |
| RMSE | 4.04 | 6.86 |
| MAE | 1.14 | 2.14 |
| R² (log 척도) | 0.906 | 0.804 |

\* 기준선: 토양·기상을 보지 않고 "그 작물·재배철의 과거 중앙값"으로만 예측한 경우

- 과제 목표인 **정확도(R²) 0.80 이상**을 넘었습니다. 회귀 문제라서 정확도는 결정계수 R²로 쟀습니다.
- 학습 데이터 R²는 0.982로 평가보다 높아서 약간의 과대적합은 있지만, 처음 보는 미래 연도에서도
  0.898이 나와서 일반화에는 문제가 없다고 판단했습니다.
- 순열 중요도(`figures/final_evaluation.png`)를 보면 작물 종류가 가장 중요하고, 그다음이
  토양 질소와 인입니다. 작물마다 수확량 규모 자체가 다르니 당연한 결과이고, 기준선(0.705)과의
  차이가 토양·기상 정보가 더해 준 몫입니다.

## 7. 프로그램 기능 (app.py)

아래 예시는 모두 같은 조건으로 실행한 결과입니다.
토양 N 78, P 45, K 22, pH 6.8 / 연평균 기온 28℃, 연 강수량 1,100mm, 연평균 습도 70%

실행하면 메뉴가 나오고, 토양·기상 조건은 한 번 입력하면 다른 기능에서도 그대로 다시 쓸 수 있습니다.
입력값은 학습 데이터 범위를 벗어나면 다시 입력받습니다(범위 밖은 예측을 믿기 어렵기 때문).

### ① 작물 수확량 예측
작물과 재배철을 고르면 예상 수확량을 알려 줍니다. 그 작물의 '보통 해' 수확량(과거 중앙값)과
비교해서 몇 %인지, 이 작물의 평가 오차가 어느 정도인지도 같이 보여 줍니다. 재배 면적을 넣으면
총 생산량도 계산합니다.

```
▶ 벼 (Rice) · 여름작
  예상 수확량 : 2.74 톤/ha
  보통 수확량 : 2.54 톤/ha (과거 243건의 중앙값)
  보통 대비   : 108% → 보통
  예상 오차   : ±0.40 톤/ha 안팎 (2017~2020년 평가에서 이 작물의 오차 중앙값)
```

### ② 토양 맞춤 작물 추천 (TOP 5)
재배철을 고르면, 그 철에 30건 이상 재배 기록이 있는 작물을 모두 예측해서 순위를 매깁니다.
작물마다 수확량 단위와 규모가 너무 달라서(사탕수수 수십 톤 vs 참깨 1톤 미만) 예측값을 그대로
비교하면 항상 사탕수수가 1등이 됩니다. 그래서 **적합도 = 예상 수확량 ÷ 그 작물의 보통 수확량**으로
순위를 매겼습니다. 1.2면 그 작물이 평년보다 20% 더 잘 된다는 뜻입니다.

```
▶ 카리프(여름 우기작, 6~10월) 후보 34종 중 적합도 상위 5종
  순위  작물                                적합도       예상 수확량       보통 수확량
  1     강황 (Turmeric)                       4.37        4.53 톤/ha        1.04 톤/ha
  2     담배 (Tobacco)                        2.90        5.19 톤/ha        1.79 톤/ha
  ...
```

### ③ 토양 개선 시뮬레이션
작물을 고르면 질소·인·칼륨·pH를 하나씩 조금씩 바꿔 가며(예: 질소 ±10·±20, pH ±0.3·±0.5) 다시
예측해서, 수확량이 가장 많이 오르는 조정과 일반적인 관리 방법(석회 시용, 인산 비료 등)을 알려
줍니다. 기상은 사람이 바꿀 수 없으니 고정합니다.

```
▶ 사탕수수 (Sugarcane) · 현재 예상 수확량 82.70 톤/ha
  조정                         예상 수확량      변화
  토양 인(P) -10               88.26 톤/ha     +6.7%
  토양 질소(N) +10             85.26 톤/ha     +3.1%
  ...
  가장 효과적인 조정: 토양 인(P) -10 → 수확량 +6.7%
```

## 8. 실행 방법

Python 3.13, VS Code 터미널에서 실행했습니다. 저장된 모델 파일은 scikit-learn 버전에 민감해서
`requirements.txt`에 학습할 때 쓴 버전을 그대로 적어 두었습니다(scikit-learn 1.9.1, pandas 3.0.5,
numpy 2.5.3). 다른 버전을 쓰면 `python train_model.py`로 모델을 다시 만들면 됩니다.

```
pip install -r requirements.txt
python collect_data.py   # 1) 원시 데이터 내려받기 → data/raw/, data/crop.db
python train_model.py    # 2) 전처리·모델 비교·튜닝·평가 → models/, figures/ (약 6분)
python app.py            # 3) 프로그램 실행
```

학습된 모델(`models/crop_yield_model.joblib`)을 저장소에 같이 올려 두었기 때문에, 바로 써 보고
싶으면 `pip install -r requirements.txt` 후 `python app.py`만 실행해도 됩니다.
`train_model.py`를 실행했을 때의 전체 출력은 [docs/train_log.txt](docs/train_log.txt)에 있습니다.

## 10. 개발 과정 (Git)

Git 강의에서 배운 **토픽 브랜치 방식**으로 개발했습니다. 기능마다 `feature/...` 브랜치를 만들어
작업하고 커밋한 뒤, `master`로 돌아와 `git merge --no-ff`로 병합했습니다. `--no-ff`를 쓴 이유는
fast-forward로 합치면 기능 단위 경계가 사라지기 때문입니다. 병합이 끝난 브랜치는 `git branch -d`로
지웠고, 이미 푸시한 커밋은 리베이스하지 않았습니다(강의에서 말한 리베이스의 위험성).

| 순서 | 브랜치 | 내용 |
|---|---|---|
| 1 | (master) | 프로젝트 초기 설정 |
| 2 | `feature/data-collection` | 원시 데이터 수집·SQLite 적재 |
| 3 | `feature/model-training` | 전처리·모델 비교·튜닝·저장 |
| 4 | `feature/yield-prediction` | 기능 ① 작물 수확량 예측 |
| 5 | `feature/crop-recommendation` | 기능 ② 토양 맞춤 작물 추천 |
| 6 | `feature/soil-simulation` | 기능 ③ 토양 개선 시뮬레이션 |
| 7 | `docs/readme` | 문서 정리 |

## 11. 한계와 앞으로 해 볼 것

- **토양값이 주(州) 단위 평균입니다.** 30개 주마다 값이 하나뿐이라, 학습에 쓰인 토양 조합은 사실상
  30가지입니다. 그래서 모델 입장에서 토양 4개 값은 '어느 주와 비슷한 땅인가'를 알려 주는 역할에
  가깝고, 실제 밭 하나하나의 토양 차이를 배운 것은 아닙니다. 특히 ③ 토양 개선 시뮬레이션은
  인과관계가 아니라 "토양이 이런 주들에서는 수확량이 이랬다"는 경향을 보여 주는 것이고, 트리
  모델이라 값을 조금 바꿔도 결과가 계단처럼 같게 나오는 경우가 있습니다. 실제 시비 처방은 토양
  검정 기관의 처방서를 따라야 합니다. 토양·기상 표의 원래 출처가 밝혀져 있지 않은 점도 한계입니다.
- **이상치 제거를 학습·평가 분할 전에 했습니다.** 입력 오류를 걸러내는 목적이었지만, 평가 데이터도
  같은 기준으로 정리된 상태라 실제 성능보다 약간 좋게 나왔을 수 있습니다.
- **인도 데이터입니다.** 기후와 작물 구성, 토양 검정 단위가 우리나라와 다르기 때문에 국내 밭에
  그대로 쓰기는 어렵습니다. 농촌진흥청 '흙토람'의 토양 검정 데이터와 국내 작물 통계를 연결해
  보는 것이 다음 목표입니다.
- **섬유작물(목화·황마 등)의 수확량은 '베일/ha'** 단위라 다른 작물(톤/ha)과 직접 비교할 수 없습니다.
  추천에서는 적합도(보통 대비 비율)를 써서 이 문제를 피했습니다.
- 작물 종류가 예측력의 대부분을 차지합니다. 토양·기상이 더해 준 몫은 기준선 대비 R² 약 0.19입니다.
